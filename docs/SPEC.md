# 今のアプリの振る舞い

アプリ（Irocam）を使う人から見える、今の振る舞いを書く。振る舞いを変える PR では、同じ PR でこのファイルも直す。なぜそうしたかは [docs/adr/](adr/)、言葉の意味は [CONTEXT.md](../CONTEXT.md)、これからやることは GitHub の issue にある。

カメラを中心にし、撮影時にレシピで色を決めて撮って出しで使う（[ADR 0008](adr/0008-camera-first-straight-out-of-camera.md)）。作り直しの残りは、確認画面（#57）、レシピの編集シート（#58）、Settings の整理（#59）、撮影の手応え（#60）。

## カメラ画面

アプリはカメラ画面で起動し、画面は縦向きに固定されている。使うのは背面のメインカメラだけ。

- **配置**：プレビューは縦 2:3（保存される 3:2 を正位置に回したもの）。上は右上の歯車（Settings を開く）だけ。下は上から、画角のボタン、レシピの帯、サムネイル・シャッター・露出補正のボタンの順に並ぶ
- **画角**：24 / 28 / 35mm のボタンを押すと、その画角に直接切り替わる。初期値は 35mm。メインカメラのセンサーを 3:2 で切り出す（[ADR 0002](adr/0002-12mp-bayer-raw-input.md)）
- **レシピの帯**：レシピを横に並べ、左右にスワイプして中央に来たものを使う。名前をタップしてもそこへ動く。プレビューの色はその場で変わる
- **露出補正**：右下のボタンに今の値（「±0」「+⅓」など）が出て、0 以外なら黄色になる。押すとレシピの帯の場所が −3〜+3 の目盛り（1/3 段刻み）に変わり、スワイプかタップで合わせる。もう一度押すか、3 秒触らないと帯に戻る。値は次に起動したときも残る
- **ピントと露出**：タップした点でピントと露出を合わせ続け、次のタップまで場面が変わっても中央には戻らない。ピントの枠は起動時から中央に出ていて消えない。枠は画面上の位置で持つので、画角を変えても同じ場所に残り、そこに写っているものに合わせ直す。長押しで AE/AF ロックになり（枠が黄色、そばに「AE/AF LOCK」）、次のタップで解ける。ロック中も露出補正は効く
- **横持ち**：配置はそのままで、文字とアイコンだけを読める向きに回す。逆さ持ちでは回さない
- **プレビュー**：選んだレシピのルックを掛ける。プレビューの映像は RAW ではなく iPhone が作った動画のコマなので、保存される写真とは一致しない。雰囲気（色の傾向、彩度、コントラスト）が伝われば十分とし、グレインは掛けない
- **サムネイル**：最後に撮った写真を小さく出す。押しても今は何も起きない（#57）
- **知らせ**：失敗（許可がない、撮影や保存の失敗）は、上に短い通知を 3 秒出す。RAW のサイズや保存の結果などの状態は、Settings の開発用でオンにしたときだけ 1 行で出す
- **撮影**：シャッターを押した時点のレシピと画角で現像する。押したあとに変えても、効くのは次の 1 枚から。Bayer RAW が使えない端末ではシャッターを押せない

## レシピ

レシピは、ルック 1 つと調整（明るさ、WB のずらし、ハイライト / シャドウ、グレインの強さと大きさ）の組に名前を付けたもの。

- 最初は、組み込みのルックごとに調整なしのレシピが 1 つずつある（ナチュラル、ネガフィルム、アメリカ）。画面の名前は商標を避けたもので、中の値は元のまま（Provia、Classic Chrome、Portra 400VC）なので、名前を変えても保存したレシピは読める
- LUT を読み込むと、そのルックだけを使うレシピが 1 つ自動で足される。LUT の名前を変えると、そのとき自動で足したレシピの名前も、まだ名前を変えていなければ追従する（調整を変えていても追従する）。LUT を消すと、自動で足したレシピのうち調整を変えていないものは消え、ほかのレシピは組み込みのルックに戻る
- 今できる操作は、選ぶこと（カメラ画面の帯、Settings）と、選んでいるレシピの調整を現像画面で変えることだけ。複製、名前の変更、並べ替え、隠すは #58
- 撮るたびに、写真と、使ったレシピの名前と中身、画角を記録する。あとでレシピを直したり消したりしても、撮ったときのものがわかる

## Settings

カメラ画面の歯車からシートで開く。

- **撮影**：レシピ、画角、露出補正。カメラ画面と同じ値を読み書きする
- **LUT の読み込み**：ファイル App から .cube を読み込む（下の「LUT の読み込み」）。一覧から名前を変える（空にするとファイル名に戻る）、スワイプで消す
- **保存**：DNG も写真ライブラリに保存するか（初期値はオン）
- **開発用**：カメラ画面に状態を出すか（初期値はオフ）、DNG を選んで現像し直す（現像画面を開く）
- **カメラの RAW 対応（開発用）**：背面の広角・超広角・望遠と前面のカメラで、Bayer RAW と ProRAW が撮れる形式が並ぶかと、写真の最大サイズを調べる。撮影には影響しない
- **このアプリ**：ビルドした commit と日付

## 現像画面

Settings の開発用からだけ開く、色の検証のための画面。写真ライブラリから DNG を選び、ルック、画角、調整を変えて見比べ、HEIC で保存できる。

- 変えるのは今選んでいるレシピそのもので、カメラの撮影にもそのまま効く。画角もカメラ画面と共有している
- 保存するのは HEIC だけで、撮影の記録には残らない

## 保存

- HEIC は必ず保存する。DNG は Settings でオンのときだけ保存する
- HEIC と DNG は別々の写真として保存する。DNG を HEIC の付属のファイルにすると、写真ライブラリが拒否するため（#5）
- 撮影時の端末の向きを記録し、横持ちの写真は横位置で保存する
- HEIC には、撮ったアプリのバージョン（commit と日付）を書き込む
- 現像に失敗したときは、DNG がオンなら DNG だけを保存して知らせ、オフなら何も保存せずに知らせる
- 写真ライブラリには追加の許可だけを求める

## LUT の読み込み

読み込んだ .cube はルックとして使える。入力は F-Log2 / F-Gamut（富士の公式 F-Log2 用 LUT はそのまま使える）か、S-Log3 / S-Gamut3.Cine、S-Log3 / S-Gamut3。何用の LUT かは、ファイル名と、中に書かれたタイトルやコメントから判定する。S-Log3 用は読み込むときに F-Log2 用に焼き直す（[ADR 0007](adr/0007-detect-imported-lut-input-log.md)）。

- 判定できないもの（何も書いていない、S-Log3 で色域が書いていない、F-Log2 と S-Log3 の両方）と、未対応のもの（F-Log2 C、初代 F-Log、V-Log、C-Log など）は読み込まない
- 変な・壊れたファイル（大きすぎる、3D LUT でない、値がおかしいなど）は、アプリを落とさず、ファイルごとに理由を出して断る
- 同じ名前のファイルを読み込むと上書きする
- 名前が `FLog2_to_` で始まるもの（富士の公式の名前。大文字小文字は問わない）には、ハイライトの肩を掛ける。さらに名前に `PROVIA` を含むものには、暖色の色相も掛ける（[ADR 0004](adr/0004-x-series-corrections-only-on-fujifilm-luts.md)）
- 読み込んだファイルが消えていたら、そのレシピは組み込みのルックで現像する

## 現像の流れ

撮影した RAW は、次の順で HEIC になる。

```
12MP Bayer RAW
  → 線形の色（CIRAWFilter。Apple のノイズ除去とレンズ補正は使う。線形 1.0 より上も残す、ADR 0005）
  → 画角と 3:2 に切り出す → 撮影時の向きに戻す
  → WB のずらしとレシピの明るさ → F-Log2 に符号化（ADR 0001）
  → ルックの 3D LUT
  → 富士のルックだけ：ハイライトの肩、Provia の暖色の色相（ADR 0004）
  → ハイライト / シャドウ → グレイン
  → HEIC（sRGB として保存、ADR 0003）
```

露出アンカー（線形の 18% グレーを F-Log2 の 0.391 に置く基準のゲイン）はまだ入っていない。今は線形の値をそのまま F-Log2 に符号化している（#6）。

トーンとグレインの式は Python（`research/`）を正とし、iOS はそれに合わせる。色の正しさは、公開されている富士の RAF と撮って出し JPEG のペアを同じ流れに通し、ΔE2000 で確かめる。

## やらないこと

- 古い FinePix の CCD コンデジ風の質感（低解像度、白飛び、日付スタンプ）
- 自前のデモザイク、ノイズ除去
- 課金
- 50mm 相当（約 2.5MP になる）
- フラッシュ、セルフタイマー（#60）
