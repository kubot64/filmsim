# 設計判断（2026-09-25 時点）

議論して合意した内容。変更するときはこのファイルを更新する。

## 目的と対象

| 項目 | 決定 | 理由 |
|---|---|---|
| 目的 | まず自分用。ほかの人に配ることも考える | 色の再現精度に集中する。画面に出す名前は商標を避けた一般的なものにする |
| 狙う見た目 | X100 系のフィルムシミュレーション | 公式 LUT が基準に使え、参考作例が多い |
| 実機 | 持っていない | RAW/JPEG ペアを自分で撮れないので公式 LUT と公開データで代替 |
| 端末 | iPhone 15/16/17 世代のメインカメラ | 入力は 12MP の Bayer RAW（下の「入力形式」）。3:2 に切ると 24mm で約 10.8MP、28mm で約 8MP、35mm で約 5MP |

## 色の基準

- 富士フイルム公式の F-Log2 → フィルムシミュレーション LUT（.cube、65 grid）を「正解」とする
  - Provia / Classic Chrome を含む 10 種は GFX ETERNA 55 用パッケージに入っている。X100VI 用パッケージは ETERNA 系だけ
  - 取得は `scripts/fetch_luts.sh`（URL と SHA-256 を固定）。リポジトリにはコミットしない
- 入力側は F-Log2 データシート Ver.1.1 の式で線形 → F-Log2 に符号化する
  - `a=5.555556 b=0.064829 c=0.245281 d=0.384316 e=8.799461 f=0.092864 cut1=0.000889 cut2=0.100686685370811`
  - 18% 反射 → 0.391（IRE 38、10bit 400）、90% → 0.557（570）
- F-Gamut の原色は BT.2020 と同一、白は D65

## 入力形式

12MP（4032×3024）の Bayer RAW を使う。48MP のメインカメラでも、Bayer RAW は 48MP を指定して 12MP で返る（iPhone 15 Pro Max で確認、#5）。48MP の RAW は ProRAW しかない。

- 12MP Bayer は Apple の処理が入っていないので、色のずれを自分のパイプラインの中で切り分けられる。RAF での検証と同じ前提で進められる
- 35mm 相当に切り出すと約 2765×1843（約 5MP）になる（24mm は 4032×2688、28mm は 3456×2304）。それで足りないと感じたら、見た目が仕上がった段階で同じ場面を 48MP ProRAW でも撮って比べ、切り替えを考える（OPEN_QUESTIONS）
- 16 / 17 世代もメインカメラは同じ 48MP のクアッドピクセルなので同じと見込むが、実機では確かめていない。撮影後の表示に実際の RAW サイズが出る

## パイプライン

```
Bayer RAW (DNG、12MP)
  → CIRAWFilter（boost 0、ローカルトーンマップ 0、EDR 1 で 1.0 より上を残す。Apple のノイズ除去とレンズ補正は使う）
  → 線形 P3(D65)（センサの向き。CIRAWFilter の回転はいったん外す）
  → 画角 / 3:2 クロップ（24 / 28 / 35mm 相当。長辺に 24/画角。捨てる周辺はここから先に流さない）
  → 撮影時の向きに戻す
  → WB シフト（R/B の係数を線形空間で掛ける）
  → 露出アンカー（線形の 18% を F-Log2 の 0.391 に合わせる。要調整。OPEN_QUESTIONS 参照）
  → P3 → F-Gamut(BT.2020) 行列変換
  → F-Log2 符号化
  → 公式 3D LUT（Provia / Classic Chrome）
  → ハイライトの肩（固定。X シリーズの撮って出しに寄せる）
  → 暖色の色相（固定。Provia だけ）
  → ハイライト/シャドウトーン
  → グレイン
  → HEIC 書き出し（sRGB としてタグ付け。コード値は変換しない）
```

LUT は F-Log2 のコード値をそのまま引く。出力のコード値は変換せず、sRGB として表示・保存する。LUT の出力は BT.709 ガンマだが、比べる相手のカメラの JPEG が sRGB なので、ΔE（`metrics.py`）も HEIC のタグも sRGB に揃える（#13）。P3 へ広げる変換はしない。

LUT の後ろに、ハイライトの肩を持ち上げる固定の補正を入れる（`tone.x_series_shoulder`、#16）。公式 LUT は GFX 用で、X シリーズの撮って出し JPEG と比べると、参照 L* 80 以上が 7 機種 15 組のどれでも暗い。輝度が 0.6 を超えた部分を γ 0.5 の方向へ smoothstep で寄せ、RGB は輝度の比で掛けるので色相は変わらない。0.6 以下と 1.0 は動かない。1 機種を抜く交差検証でも、ハイライト帯の ΔE は 7 機種中 6 機種で下がった。唯一 GFX 50S II では悪化したので、これは LUT の性質ではなく、X シリーズの見た目に寄せる補正として扱う。

Provia では、ハイライトの肩の後ろで、赤から黄の色相を赤へ 7° 戻す（`hue.x_series_warm_hue`、#11）。公式 LUT のままだと、X シリーズの撮って出しより赤が +5°、橙が +7〜8° 黄色寄りになる。同じ RAF を LibRaw と CIRAWFilter のどちらで読んでも同じだけずれるので、RAW の色変換ではなく、LUT かカメラ内の処理の差として扱う。LUT 出力のコード値を BT.709 の Y'CbCr にし、Cb/Cr の角度だけを回す（中心 140°、幅 ±80° の raised cosine。赤は約 103°、橙は約 138°、黄は約 175°）。Y' と色差の長さは変わらず、緑より先の色相とグレーは動かない。Provia 7 組（X100VI 4、X-T5 3）で当てはめ、2 つのエンジンと 1 機種を抜く交差検証のどれでも、暖色の ΔE は下がり（例 4.29 → 1.84）、画像全体の ΔE が悪化した組はなかった。Classic Chrome はずれが小さく、同じ回転で 7 組中 2〜3 組の全体の ΔE が悪化したので掛けない。

## 富士以外のルック

Leica Standard と Kodak Portra 400VC を足す。Portra 400VC の LUT は焼いた。Leica はまだ。どちらも富士の LUT と同じ場所に入る「F-Log2 のコード値 → 表示のコード値」の 3D LUT として作る。入力の側（線形 → F-Log2）は変えないので、アプリのパイプラインはそのまま使え、LUT を差し替えるだけで済む。

- **Leica Standard**：公式の LUT はないが、DNG と撮って出し JPEG のペアはある。ペアから LUT を最小二乗で当てはめる（`research/filmsim/lutfit.py`、`scripts/fit_look.py`）。写真に出てこない色域は、近くで当てはめた補正をなめらかに延ばして埋める。当てはめに使わなかった組との ΔE で検証する
- **Portra 400VC**：ネガフィルムなので RAW と JPEG のペアがない。Kodak の技術資料（特性曲線と色素の分光濃度）で骨格を作り、作例と見比べて寄せる。#31 のコダクロームと同じやり方
- 富士専用の補正（ハイライトの肩、Provia の暖色の色相）は、富士の公式 LUT にだけ掛ける。当てはめた LUT には、そのカメラのハイライトが最初から入っている。Python では `pipeline.FUJIFILM_FILM_SIMS`、公式でないファイルは `film_sim_key` が `"fitted"` を返す
- 露出アンカー：当てはめるときの露出（`--ev`）を、アプリで 18% グレーが F-Log2 の 0.391 に来る置き方と揃える必要がある。Leica の DNG で中間グレーがどこに来るかは、ペアを集めてから決める（OPEN_QUESTIONS）

## Portra 400VC のデータ

Kodak の技術資料（TSC 0597-2 日本語版、2006。Portra 160NC / 160VC / 400NC / 400VC / 800 をまとめた 1 冊）の 400VC のページから、ベクター図の線をそのまま数値にした（`research/filmsim/portra400vc.py`）。特性曲線（Status M、C-41）、中間グレーと D-min の分光濃度、3 層の分光感度。直線部のガンマは R 0.58、G 0.58、B 0.67。基準露光（中間グレー）は log H = −1.44。

これを使って、ネガとプリントを計算で通す LUT を焼いた（`research/filmsim/negative.py`、`scripts/bake_negative.py`、`ios/FilmSim/LUTs/Portra400VC_65grid.cube`）。入出力は公式 LUT と同じ（F-Log2 → sRGB のコード値）。

1. 線形 BT.2020 → 3 層の露光量：分光感度から 3x3 行列を作る。ColorChecker 24 色の分光反射率 × D65 で、RGB と各層の露光量を最小二乗で結ぶ。昼光用フィルムなので、グレーは 3 層で等しくなるよう行をそろえる
2. 露光量 → トーン：3 本の特性曲線をそれぞれのガンマで割って平均した 1 本を、3 チャンネルに共通で掛ける。足で影が詰まり、肩でハイライトが残る形はここから来る。チャンネルごとに別の曲線を掛けると、足の始まりがずれていてグレーに色が付いた（ColorChecker の黒が紫になった）。スキャナーのチャンネルごとのレベル合わせに当たる
3. プリント：輝度と、各チャンネルの輝度からのずれに分けて扱う（log 単位）。ずれに彩度を掛け、輝度に S 字の曲線を掛ける。影は、フィルムのベース（D-min）が中間グレーから決めた段数だけ下で黒になるよう、輝度だけを引き延ばす
4. スキャン：表示の線形 RGB にスキャナーの 3x3 の色行列を掛ける。各行の和は 1 なので、グレーはグレーのまま

3 と 4 の値は資料にないので、ColorChecker が写った Portra 400VC の実際のスキャン（Flickr の tgray1 さんのアルバム「Portra 400VC test」、`research/filmsim/portra400vc_scan.py` に 24 色の測定値）に当てはめた。スキャンの明るさとグレーのバランスは自由にして、24 色の ΔE2000 の平均を最小にした。平均 3.3、中央値 2.8（何もしない本来の色だとスキャンと 17 違う）。値はコントラスト 1.83、彩度 1.15、影 9.7 段、黒 0、色行列は R 行が (1.267, −0.317, 0.050)。赤がスキャンどおり 36° のオレンジ寄りになるのは、この色行列による（行列なしでは 18°）。ユーザーの作例 5 枚（深い青空と赤い風船、黄緑の椅子とバイオリン、ポートレート 2 枚、赤いギンガムチェック）でも、赤はオレンジ寄り（25〜38°）、青はシアン寄りだった。富士専用の補正（肩、暖色の色相）は掛けない

- スキャンは 18% の中間グレーより約 1.2 段明るく置かれていた。アプリの LUT はほかのフィルムシミュレーションと同じ 18% の置き方で焼いたので、スキャンのような明るく軽い見た目にするなら、撮影時の露出補正を上げる
- 同じアルバムの −4〜+5 段のブラケットは、スキャナーがコマごとに明るさをそろえていて、トーンカーブは測れない。+5 段でも破綻せず、−3 段から黒が浮いて白が落ちる（足が尽きる）のは、モデルの形と合う
- 格子は 65（公式 LUT と同じ）。33 では三線形補間で中間グレーが 0.166 / 0.172 / 0.171 になり、わずかにシアンに寄った

CIRAWFilter の `extendedDynamicRangeAmount` は 1 にする（#24）。0 だと線形の 1.0 で切られ、光源のまわりに残っている赤と青のデータ（最大で約 1.3 段）を捨てる。1.0 は Provia を通しても sRGB 223 にしかならないので、光源がくすんだ明るいグレーで止まっていた。1 にすると、光源は 241〜246 まで白くなり、自動販売機の画面のような明るい面の細部も戻る。中間調は変わらない。センサーが完全に飽和した部分は CIRAWFilter が推定で埋める（EDR に比例して最大値が増えるので推定とわかる）。線形 1.0 付近を式で引き伸ばす案は、細部が戻らず、飽和の手前のノイズを増やしたので採らなかった。

画角のクロップはセンサの長辺を横にしたバッファに掛ける。縦持ちの DNG を CIRAWFilter が先に回転した状態で幅に 24/35 を掛けると、約 47mm 相当になる。

トーンとグレインの重み・振幅・σ は `research/filmsim/tone.py` と `grain.py` を正とし、Swift / Metal はそれに合わせる。グレインの乱数分布は一致しない。Python は正規乱数で、iOS は `CIRandomGenerator` の一様乱数をぼかして標準偏差だけ `grain.unit_noise_gain` に合わせている。σ=0.6 では分布の形が違う。色行列は線形 RGB に WB と露出を掛けてから P3 → F-Gamut する（`out = M · (rgb × gains)`）。プレビューのグレイン粒径だけ解像度に比例させる。

## スコープ

- フィルムシミュレーションは 3 種。画面の名前は商標（富士フイルム、コダック）を避けて、ナチュラル（Provia）、ネガフィルム（Classic Chrome）、アメリカ（Portra 400VC）にした。コードの case 名と保存される値は元のまま（保存済みのレシピが読める）
- LUT の読み込み：Settings からファイル App の .cube を読み込み、フィルムシミュレーションの一覧に足す。入力は F-Log2 / F-Gamut で、富士フイルムの公式 F-Log2 用 LUT はそのまま使える。ファイル名が `FLog2_to_` で始まるもの（公式の名前）には、標準の富士の色と同じ補正（ハイライトの肩、PROVIA なら暖色の色相）を掛ける。ほかの LUT はそのまま。読み込むときに 3D LUT として読めるかを確かめ、Application Support/ImportedLUTs に写す。S-Log3 用の LUT（S-Gamut3.Cine か S-Gamut3）も読み込める。何用の LUT かは使う人に選ばせず、ファイル名と TITLE・コメント行に書かれた「F-Log2」「S-Log3」「S-Gamut3.Cine」などから判定する（`LUTInputDetection`）。.cube には入力の Log を書く決まった欄がないが、実際のファイルはたいてい名前に書いてある（富士の FLog2_to_…、Sony の SLog3SGamut3.CineTo…）。判定できないもの（何も書いていない、S-Log3 で色域が書いていない、F-Log2 と S-Log3 の両方）と未対応のもの（F-Log2 C、初代 F-Log、V-Log、C-Log など）は読み込まない。違う Log として読むと、エラーにならないまま色がおかしくなるため。S-Log3 用は、F-Log2 のコード値 → 線形 → S-Gamut3(.Cine) → S-Log3 のコード値 → その LUT、を 65 grid の F-Log2 用 LUT に焼き直して保存する（`LUTInput`、`CubeLUT.convertedToFLog2`）。撮影時のパイプラインは変えない。フィルム風の LUT は F-Log2 用より S-Log3 用のほうがずっと多いため。ほかのメーカーの公式 LUT はたいてい Log を標準的な見た目に直す変換用で、読めてもそのメーカーの写真モードにはならない。読み込んだ LUT には Settings の一覧で好きな名前を付けられ、`UserDefaults`（`LUTDisplayNames.storageKey`）に覚えておく。空にするとファイル名に戻る。付けるのは表示の名前だけで、中ではファイル名で扱うので、名前を変えても選んでいる色は外れない。レシピは読み込んだ LUT の名前を持ち、そのファイルが消されていたら直前の組み込みの色で現像する。公式 LUT をアプリに同梱して配ると再配布になるので、配布版では富士の色は各自が読み込む形にできる
- LUT 以外の調整項目は グレイン、H/S トーン、WB シフト の 3 つ。カラークローム効果と明瞭度は後回し
- カメラで撮った写真は、最後に使ったレシピで現像する（#8）。レシピは現像画面と共有し、`UserDefaults` の 1 か所（`Recipe.storageKey`）に JSON で保存する。カメラ画面ではフィルムシミュレーションだけを切り替えられ、ほかの設定は現像画面で変える。既定値から変えた設定はカメラ画面に 1 行で出す。レシピはシャッターを押した時点のものを使う
- カメラ画面の操作（#33）：プレビューをタップするとその点でピントと露出を 1 回合わせ、場面が変わると中央の連続 AF/AE に戻る。長押しは AE/AF ロックで、次のタップまで固定する。± ボタンは撮影時の露出補正（1/3 段、±3）で、センサーに届く光を変える。レシピの Exposure は現像時の明るさなので別物。露出補正は `UserDefaults`（`ExposureCompensation.storageKey`）に保存し、次に起動したときも残す。フィルムシミュレーションと露出補正は Settings 画面でも変えられ、カメラ画面と同じ値を読み書きする
- 撮影中のプレビューは色を掛けない。アプリは縦向き固定なので、プレビュー枠は縦の 2:3（保存される 3:2 を正位置に回したもの）にする
- 保存は HEIC を常に、DNG は設定で切替（初期はオン）。HEIC と DNG は別々の写真として保存する。DNG を HEIC の `.alternatePhoto` にすると写真ライブラリが拒否する（#5）
- メインカメラを 24 / 28 / 35mm 相当にセンサークロップ、3:2 固定。初期値は 35mm（X100 の画角）。35mm 固定はほかの人には狭く、解像度も約 5MP に下がるので選べるようにした。50mm は約 2.5MP になるので入れない
  - 画角はカメラ画面の mm ボタン（押すたびに 24 → 28 → 35）、Settings、現像画面で変えられ、`UserDefaults`（`FocalLength.storageKey`）の 1 か所に保存する。撮影はシャッターを押した時点の画角で現像する。DNG はセンサー全体なので、現像画面では撮ったあとで画角を変えられる
  - 超広角と望遠は、Bayer RAW が撮れるかと色・露出が揃うかを実機で確かめてから足す（ROADMAP）

## 検証

- DPReview 等の公開サンプルの RAF と撮って出し JPEG のペアを使う
- RAF を LibRaw で線形 BT.2020 に現像 → F-Log2 → 公式 LUT → JPEG と ΔE2000 で比較
- Python（`research/`）で先に組んで確定させ、確定した式と中間画像を Swift 側のテスト期待値にする

## やらないこと

- 古い FinePix の CCD コンデジ風の質感（低解像度、白飛び、日付スタンプ）
- 自前のデモザイク・ノイズ除去
- ライブプレビューへの LUT 適用（MVP では）
- 課金
