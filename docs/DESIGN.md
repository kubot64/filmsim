# 設計判断（2026-09-25 時点）

議論して合意した内容。変更するときはこのファイルを更新する。

## 目的と対象

| 項目 | 決定 | 理由 |
|---|---|---|
| 目的 | まず自分用 | 商標や課金を気にせず色の再現精度に集中する |
| 狙う見た目 | X100 系のフィルムシミュレーション | 公式 LUT が基準に使え、参考作例が多い |
| 実機 | 持っていない | RAW/JPEG ペアを自分で撮れないので公式 LUT と公開データで代替 |
| 端末 | iPhone 15/16/17 世代のメインカメラ | 入力は 12MP の Bayer RAW（下の「入力形式」）。35mm 相当に切ると約 5MP |

## 色の基準

- 富士フイルム公式の F-Log2 → フィルムシミュレーション LUT（.cube、65 grid）を「正解」とする
  - Provia / Classic Chrome を含む 10 種は GFX ETERNA 55 用パッケージに入っている。X100VI 用パッケージは ETERNA 系だけ
  - 取得は `scripts/fetch_luts.sh`（URL と SHA-256 を固定）。リポジトリにはコミットしない
- 入力側は F-Log2 データシート Ver.1.1 の式で線形 → F-Log2 に符号化する
  - `a=5.555556 b=0.064829 c=0.245281 d=0.384316 e=8.799461 f=0.092864 cut1=0.000889 cut2=0.100686685370811`
  - 18% 反射 → 0.391（IRE 38、10bit 400）、90% → 0.557（570）
- F-Gamut の原色は BT.2020 と同一、白は D65

## 入力形式

12MP（4032×3024）の Bayer RAW を使う。48MP のメインカメラでも、Bayer RAW は 48MP を指定して 12MP で返る（iPhone 15 Pro Max で確認、#5）。48MP の RAW は ProRAW しかない。

- 12MP Bayer は Apple の処理が入っていないので、色のずれを自分のパイプラインの中で切り分けられる。RAF での検証と同じ前提で進められる
- 35mm 相当に切り出すと約 2765×1843（約 5MP）になる。それで足りないと感じたら、見た目が仕上がった段階で同じ場面を 48MP ProRAW でも撮って比べ、切り替えを考える（OPEN_QUESTIONS）
- 16 / 17 世代もメインカメラは同じ 48MP のクアッドピクセルなので同じと見込むが、実機では確かめていない。撮影後の表示に実際の RAW サイズが出る

## パイプライン

```
Bayer RAW (DNG、12MP)
  → CIRAWFilter（boost 0、ローカルトーンマップ 0、Apple のノイズ除去とレンズ補正は使う）
  → 線形 P3(D65)（センサの向き。CIRAWFilter の回転はいったん外す）
  → 35mm / 3:2 クロップ（長辺に 24/35。捨てる周辺はここから先に流さない）
  → 撮影時の向きに戻す
  → WB シフト（R/B の係数を線形空間で掛ける）
  → 露出アンカー（線形の 18% を F-Log2 の 0.391 に合わせる。要調整。OPEN_QUESTIONS 参照）
  → P3 → F-Gamut(BT.2020) 行列変換
  → F-Log2 符号化
  → 公式 3D LUT（Provia / Classic Chrome）
  → ハイライトの肩（固定。X シリーズの撮って出しに寄せる）
  → ハイライト/シャドウトーン
  → グレイン
  → HEIC 書き出し（sRGB としてタグ付け。コード値は変換しない）
```

LUT は F-Log2 のコード値をそのまま引く。出力のコード値は変換せず、sRGB として表示・保存する。LUT の出力は BT.709 ガンマだが、比べる相手のカメラの JPEG が sRGB なので、ΔE（`metrics.py`）も HEIC のタグも sRGB に揃える（#13）。P3 へ広げる変換はしない。

LUT の後ろに、ハイライトの肩を持ち上げる固定の補正を入れる（`tone.x_series_shoulder`、#16）。公式 LUT は GFX 用で、X シリーズの撮って出し JPEG と比べると、参照 L* 80 以上が 7 機種 15 組のどれでも暗い。輝度が 0.6 を超えた部分を γ 0.5 の方向へ smoothstep で寄せ、RGB は輝度の比で掛けるので色相は変わらない。0.6 以下と 1.0 は動かない。1 機種を抜く交差検証でも、ハイライト帯の ΔE は 7 機種中 6 機種で下がった。唯一 GFX 50S II では悪化したので、これは LUT の性質ではなく、X シリーズの見た目に寄せる補正として扱う。

35mm クロップはセンサの長辺を横にしたバッファに掛ける。縦持ちの DNG を CIRAWFilter が先に回転した状態で幅に 24/35 を掛けると、約 47mm 相当になる。

トーンとグレインの重み・振幅・σ は `research/filmsim/tone.py` と `grain.py` を正とし、Swift / Metal はそれに合わせる。グレインの乱数分布は一致しない。Python は正規乱数で、iOS は `CIRandomGenerator` の一様乱数をぼかして標準偏差だけ `grain.unit_noise_gain` に合わせている。σ=0.6 では分布の形が違う。色行列は線形 RGB に WB と露出を掛けてから P3 → F-Gamut する（`out = M · (rgb × gains)`）。プレビューのグレイン粒径だけ解像度に比例させる。

## スコープ

- 初期のフィルムシミュレーションは Provia と Classic Chrome の 2 種
- LUT 以外の調整項目は グレイン、H/S トーン、WB シフト の 3 つ。カラークローム効果と明瞭度は後回し
- 撮影中のプレビューは色を掛けない。アプリは縦向き固定なので、プレビュー枠は縦の 2:3（保存される 3:2 を正位置に回したもの）にする
- 保存は HEIC を常に、DNG は設定で切替（初期はオン）。HEIC と DNG は別々の写真として保存する。DNG を HEIC の `.alternatePhoto` にすると写真ライブラリが拒否する（#5）
- メインカメラを 35mm 相当にセンサークロップ、3:2 固定

## 検証

- DPReview 等の公開サンプルの RAF と撮って出し JPEG のペアを使う
- RAF を LibRaw で線形 BT.2020 に現像 → F-Log2 → 公式 LUT → JPEG と ΔE2000 で比較
- Python（`research/`）で先に組んで確定させ、確定した式と中間画像を Swift 側のテスト期待値にする

## やらないこと

- 古い FinePix の CCD コンデジ風の質感（低解像度、白飛び、日付スタンプ）
- 自前のデモザイク・ノイズ除去
- ライブプレビューへの LUT 適用（MVP では）
- App Store 配布のための商標回避や課金
