# 未決事項

設計時に決める必要があるが、まだ結論が出ていないもの。

- **露出アンカー**: CIRAWFilter の線形出力で「18% グレー」がどの値になるか。F-Log2 の 0.391 に合わせるためのゲインを、RAF ペアの ΔE スイープで決める（`compare_raf.py --sweep-ev`）。富士の撮って出し 15 組（Provia 7 組：X100VI、X-T5。Classic Chrome 8 組：X-H1、X-Pro2、X-T50、X-Pro3、GFX 50S II）では、ハイライトの肩の補正（#16）を入れた状態で、LibRaw の線形出力に対して DR100 は +1.00〜+1.25 EV、DR200 は +1.88〜+2.12 EV（DR200 はカメラが 1 段暗く撮る分）。機種やフィルムシミュレーションが違っても同じアンカーに揃う。ΔE 中央値は Provia で 2.2〜2.7、Classic Chrome で 1.3〜4.8。LibRaw 基準の値なので iPhone の CIRAWFilter にはそのまま使えない
- **ハイライトの余裕**: F-Log2 は 18% から +8 段以上を想定するが、iPhone は少ない。iPhone 15 Pro Max のセンサーは、DNG の白レベル 4095 の 85.6%（生の値で約 3580）で飽和する。自動露出が置く中間グレーから、緑は 2.3〜4 段で飽和する。赤と青にはさらに約 1.3 段残っていて、それは CIRAWFilter の EDR 1 で使うことにした（DESIGN.md、#24）。完全に飽和した部分の出し方（今は CIRAWFilter の推定に任せている）は、昼の屋外でも確かめる
- **CIRAWFilter のノイズ除去とシャープ**: Apple のデフォルトはフジより強い。`luminanceNoiseReductionAmount` 等をどこに固定するか
- **48MP ProRAW への切り替え**: 入力は 12MP の Bayer RAW に決めた（DESIGN.md「入力形式」）。35mm 相当に切り出すと約 5MP になる。48MP の RAW は ProRAW だけ（iPhone 15 Pro Max、#5）
  - 12MP で止まるのは、メインカメラが Quad Bayer（同じ色の 2×2 画素がかたまる配列）だからと考えられる。Apple は説明していない。48MP の細かさの Bayer 配列は物理的になく、2×2 をまとめた 12MP なら普通の Bayer として読み出せる。48MP にするにはリモザイクかデモザイクが要り、Apple はそれを自社のパイプラインの中でしかやらず、結果を ProRAW として出す
  - ProRAW は解像度が 4 倍で、多フレーム合成によりダイナミックレンジとノイズでも有利かもしれない。ただし、デモザイクとノイズ除去が済んだリニア DNG で、Apple の局所トーンマップが情報として入っている。CIRAWFilter でそれを切れるか、露出アンカー（#6）を測り直して色が崩れないかを確かめてから決める
- **ホワイトバランス**: RAW メタデータの as-shot を使うか、自前推定か。最初は as-shot
- **H/S トーンの実装**: フジの -2..+4 のスケールと同じ効きにする基準がない。まずは目視で決めた曲線を置く（`tone.py`。正のハイライトは肩を持ち上げ、正のシャドウは暗くする）
- **LUT とカメラ JPEG のトーン差**: カーブ全体の補正は別の機種に効かなかった（#10）。ハイライトの肩だけは全機種で同じ向きにずれていたので、固定の補正として入れた（#16、DESIGN.md）。GFX の撮って出しとはかえって離れるため、GFX のサンプルが増えたら、機種ごとに切り替えるかを見直す
- **LUT の機種依存**: 使っている LUT は GFX ETERNA 55 用パッケージのもの（ヘッダ `#model:GFX ETERNA 55`）。X100VI の撮って出し JPEG との ΔE が大きければ機種固有の微調整を疑う
  - 暖色のずれ（#11）：同じ RAF を LibRaw と CIRAWFilter の両方で線形にして比べた（`compare_raf.py --engine`）。Provia 7 組の中央値（こちら − カメラ）で、**色相は赤 +5.2°、橙 +7〜8.5° とどちらのエンジンでも同じ**。LibRaw の色変換ではなく、GFX 用の LUT かカメラ内の処理から来ている。**彩度はエンジンで向きが逆**（LibRaw は赤 −3.8、CIRAWFilter は赤 +2.4、青も +2.8）で、こちらは RAW の色変換から来ている。Classic Chrome 7 組でも暖色の色相は同じ向き（+1〜+6°）だが小さい。GFX 50S II の 1 組には赤と橙がほとんどなく、LUT の機種違いかカメラ内の処理かはまだ切り分けられない。色相は Provia だけ固定の回転で戻すことにした（DESIGN.md、#11）。彩度のずれ（CIRAWFilter で +2〜3）はまだ扱っていない
  - ΔE の中央値は、Classic Chrome の 7 組すべてと X-T5 の 3 組で CIRAWFilter の方が小さかった（例：X-Pro2 4.75 → 2.86、X-T50 4.01 → 2.70）。X100VI は 4 組中 3 組で LibRaw がわずかに小さい。iOS は CIRAWFilter なので、iPhone に近い条件で比べるなら `--engine ciraw` を使う
- **クラウドでの検証用 RAF**: 1 組 50MB 前後で直リンクが安定しない。ΔE 検証をクラウドでやるなら、選んだ数組をプライベートストレージに置きトークンで取得する
