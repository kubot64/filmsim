# Provia の暖色の色相のずれの切り分けと補正

富士の撮って出し JPEG と比べると、暖色だけが同じ向きにずれていた（#11）。数字は参照の彩度 C* > 20 の画素での中央値（こちら − カメラ）。

| 色相 | X100VI | X-T5 |
|---|---|---|
| 赤（0〜40°） | 彩度 −4.1、色相 +4.5° | 彩度 −3.9、色相 +5.8° |
| 橙（40〜70°） | 彩度 −1.8、色相 +9.1° | 彩度 −3.8、色相 +8.5° |
| 緑（100〜160°） | 明るさ +3.4、色相 −5.0° | 明るさ +2.3、色相 +1.0° |
| 青（220〜290°） | 色相 +1.3° | 色相 +0.8° |

採用した判断は [ADR 0004](../../docs/adr/0004-x-series-corrections-only-on-fujifilm-luts.md)。

## 原因の切り分け

原因の候補は、LibRaw の色変換、公式 LUT が GFX 用であること、カメラ内の現像にだけある処理の 3 つだった。同じ RAF を LibRaw と CIRAWFilter の両方で線形にして比べた（`compare_raf.py --engine`、#29）。Provia 7 組の中央値で：

- 色相は赤 +5.2°、橙 +7〜8.5° と、どちらのエンジンでも同じだった。したがって色相のずれは RAW の色変換ではなく、GFX 用の LUT かカメラ内の処理から来ている。iPhone でも同じように出る
- 彩度はエンジンで向きが逆だった（LibRaw は赤 −3.8、CIRAWFilter は赤 +2.4、青も +2.8）。こちらは RAW の色変換から来ていて、まだ扱っていない（#74）
- Classic Chrome 7 組でも暖色の色相は同じ向き（+1〜+6°）だが小さい

## 補正（#32）

- LUT 出力のコード値を BT.709 の Y'CbCr にし、Cb/Cr の角度だけを回す。Y' と色差の長さは変わらない
- 回転は中心 140° で −7°、±80° で 0 になる raised cosine（赤 約 103°、橙 約 138°、黄 約 175°）。グレーと、緑より先の色相は動かない
- 位置はハイライトの肩の直後、トーンカーブの前。Provia だけ

## 当てはめと検証

Provia 7 組、赤〜橙の画素（参照の C* > 20、色相 0〜70°）で当てはめた。抜粋：

| エンジン | 組 | 赤〜橙の ΔE | 赤〜橙の色相のずれ | 全体の ΔE |
|---|---|---|---|---|
| LibRaw | X100VI 1458055737 | 3.40 → 2.12 | +4.5 → −0.1° | 2.54 → 2.20 |
| LibRaw | X100VI 4308068843 | 4.29 → 1.84 | +8.1 → +0.7° | 2.59 → 2.39 |
| LibRaw | X100VI 6852444986 | 4.04 → 1.62 | +8.4 → +0.7° | 2.60 → 2.10 |
| LibRaw | X-T5 6810678047 | 3.70 → 2.71 | +5.9 → −0.6° | 2.69 → 2.31 |
| CIRAWFilter | X100VI 1458055737 | 3.55 → 1.44 | +5.1 → +0.9° | 2.31 → 1.94 |
| CIRAWFilter | X-T5 6810678047 | 2.02 → 1.35 | +5.6 → −0.7° | 1.98 → 1.79 |

- 赤〜橙のある 12 通りすべてで赤〜橙の ΔE が下がり、全体の ΔE が悪化した組はない（一番悪くて +0.01）
- 1 機種を抜く交差検証：X100VI を抜いても X-T5 を抜いても、ほぼ同じ値（−7〜−8°、中心 125〜135°）になり、抜いた機種の暖色の ΔE も下がった
- 最適値のまわりはなだらか。幅 100° が僅差で最良（差 0.01）だったが、緑（約 230°）に届かないよう 80° にした
- Classic Chrome には掛けない。ずれが小さく、Provia で当てはめた回転を掛けると 7 組中 2〜3 組で全体の ΔE が悪化した。Classic Chrome だけで当てはめても、エンジンによって値がばらばらだった
